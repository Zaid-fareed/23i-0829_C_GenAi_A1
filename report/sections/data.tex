\section{Data, Corruption Protocol and Metrics}\label{sec:data}
\textbf{Oxford-IIIT Pet (Tasks 1--3).} The dataset contains 7,393 images of 37 cat and dog breeds~\cite{parkhi2012}. Following the assignment, the official train/validation collection (3,680 images) was split 80/20 with random seed 42 into \textbf{2,944 training and 736 validation images}; the official 3,669 test images were not used for training or tuning. Category labels are ignored, and all images are converted to RGB and resized directly (bicubic) to $128\times128$. The split is stored once in \code{manifests/pets\_split.json} and reused by all three tasks; the training images are decoded once and kept in memory as \code{uint8} tensors, which is why an epoch takes seconds.

\textbf{Runtime corruption.} No corrupted copy of the data is stored. For every training image that is loaded, one of four conditions is drawn with equal probability and a fresh random specification is sampled (Table~\ref{tab:corruption}). A specification is a plain record that fully describes the corruption (probability and noise seed, kernel and sigma, or rectangle coordinates); the same pure function \code{apply\_spec} applies it during training, validation and testing, and the FastAPI back end contains a NumPy port that our tests compare against the training code. The classifier's balanced batches draw exactly $B/4$ items of each class.

\textbf{Deterministic manifests.} A validation manifest (736 entries, exactly 184 per class) and test manifests are generated once and store, for each entry, the image, corruption type, severity, parameters, mask coordinates and random seed, with a SHA-256 digest. Two test manifests exist. The first (3,669 entries) gives every test image \emph{one} condition and was used by the Kaggle evaluation scripts. The assignment, however, asks that every test image have three fixed severities of every corruption, so the final protocol uses the \textbf{full manifest: each of the 3,669 test images under all ten conditions, 36,690 inputs}. All test tables in this report use the full manifest unless stated otherwise.

\textbf{FS2K (Task 4).} FS2K~\cite{fan2022fs2k} provides 2,104 photo--sketch pairs in three sketch styles. We use the official training and test definitions; 15\% of the official training portion (1,058 pairs) forms a validation set, stratified by style with seed 42, leaving \textbf{899 training and 159 validation pairs}, and the \textbf{1,046 official test pairs} (619, 381 and 46 in styles 1, 2 and 3) are touched only for final evaluation. Photographs are resized to $128\times128$ RGB and sketches to $128\times128$ grayscale. Augmentation (horizontal flip and a random crop-and-resize) uses one random draw applied identically to both members of a pair.

\textbf{Metrics.} For restoration we report the mean absolute error (L1, images in $[0,1]$), the structural similarity index SSIM (Gaussian window of 11 pixels, $\sigma=1.5$) and PSNR in dB. PSNR of identical images is infinite, so values are clipped at 60~dB; means over conditions that contain identity-routed images should be read with this in mind. As a reference we always report the ``no restoration'' score of the corrupted input itself, because a restoration model is only useful where it beats that baseline. Classification is evaluated with accuracy, macro-averaged precision, recall and F1, per-class values and a row-normalised confusion matrix.
