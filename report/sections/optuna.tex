\section{Hyper-parameter Optimisation with Optuna}\label{sec:optuna}
Each task has its own Optuna study (TPE sampler, seed 42, SQLite files in \code{optuna\_studies/}, every trial also logged to MLflow). Trials are short and use sub-samples of the training data; the selected configuration is retrained on all data. Table~\ref{tab:space} lists the search spaces, Table~\ref{tab:optuna} the trial counts and best trials, Table~\ref{tab:selected} the final configurations and Fig.~\ref{fig:optuna} the study histories. Median pruning stopped weak trials in Tasks~1, 2 (classifier), 3 and 4; the shared specialist search is not pruned because each trial trains three models.

Three lessons stand out. Short trials favour configurations that learn fast early, which is how the first Task~1 search picked a high dropout that later under-fitted. An L1+SSIM objective cannot see colour loss, so the first specialist search picked an SSIM-heavy $\alpha$; narrowing a range after inspecting outputs is acceptable only when reported, as here. With 8--12 trials per study the searches find good, not optimal, settings.
