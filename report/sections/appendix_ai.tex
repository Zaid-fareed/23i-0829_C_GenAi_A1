\section{AI-Use Statement}\label{app:ai}
AI assistants were used for this assignment and are disclosed here with the tasks they supported and how their output was checked.

\subsection{Tools and tasks}
\begin{itemize}
\item \textbf{Claude (web chat, Anthropic):} wrote the initial project prompt and a first code base for Tasks~1--3 (data pipeline, corruptions, models, losses, Optuna and training scripts, evaluation and ONNX export scripts).
\item \textbf{Claude Code (Anthropic):} integrated and debugged that code, wrote the Task~4 cGAN, the FastAPI back end, the React/Tailwind front end, the Docker set-up, the Kaggle instructions, the evaluation, figure and table scripts, and a draft of this report, which was then revised and shortened at my request.
\item \textbf{Google Stitch:} generated the interface design from two prompts (Section~\ref{sec:app}); its HTML was a structural reference only.
\item \textbf{Kaggle notebooks (T4 GPU)} for all training; standard libraries (PyTorch, Optuna, MLflow, ONNX Runtime, FastAPI, React, Tailwind, Docker).
\end{itemize}

\subsection{Testing and corrections}
\begin{itemize}
\item \textbf{My own manual testing drove the main changes.} I ran the training on Kaggle and inspected the outputs and the application myself. Noticing that the first training run was suspiciously fast and its output poor led to the diagnosis and retraining of the autoencoder (Section~\ref{sec:t1}); noticing washed-out colours in the specialists' outputs led to the colourfulness measurement, the restricted loss-weight range and the retraining of the specialists and mixture (Section~\ref{sec:t2}); my concern about how non-square photographs were framed for sketches led to a test and to a crop option; and the first Stitch interface was hard to use (scrolling between options and results), which led to the second Stitch prompt and the revised layout.
\item \textbf{Automated checks} written with the coding assistant supported this work: tests of corruption determinism and pixel counts, balanced batches, resume-from-checkpoint, the application's endpoints (38 unit tests and a 54-check smoke test), and ONNX-versus-PyTorch comparison of every export (differences $\le2.1\times10^{-6}$). They supplement my manual testing and do not replace it.
\item \textbf{Numbers and references.} Every table value in this report is generated from saved result files by the scripts in \code{report/}. The bibliographic details of the references were checked against the publishers' or arXiv records.
\end{itemize}
